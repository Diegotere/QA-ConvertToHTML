## Introdução

Para quem não conhece, o Alterdata Backup é uma ferramenta de backup automático para os sistemas Alterdata. Até então ele estava disponível apenas para sistemas que utilizam banco de dados PostgreSQL. Contudo, ele agora funciona também o banco de dados SQL e, consequentemente, para o Bimer também. O produto Alterdata Backup oferece a realização backup manual ou programado, não sendo necessário realizar o backup direto pelo Bimer ou SQL. O Alterdata Backup possibilita ainda enviar uma cópia do arquivo de backup para nuvem, por meio da contratação de um dos planos de armazenamento. Ou seja, os clientes Bimer terão acesso gratuito ao Alterdata Backup para armazenamento local e só pagarão pelo armazenamento em nuvem caso queiram esse tipo de armazenamento. Neste manual, serão disponibilizada informações gerais sobre o funcionamento do Alterdata Backup no Bimer e outros detalhes que você precisará saber! Para consultar a documentação completa, clique aqui.


## Instalação e Funcionamento

A primeira coisa que você precisa saber é que existe o Alterdata Backup (serviço e desktop) e o Alterdata Backup Bimer. O AlterdataBackupBimer.exe foi disponibilizado a partir da versão 9.07.06.00 do sistema Bimer Desktop sendo apenas a interface de login. Sua única função é passar os dados de conexão informados pelo usuário para abrir a interface do Alterdata Backup. Por isso, antes de executar o AlterdataBackupBimer.exe, você precisará instalar o Alterdata Backup (Desktop e Serviço). Caso o serviço não esteja instalado e em execução, e tentar executar o AlterdataBackupBimer.exe, será apresentada a seguinte mensagem para o usuário: “O Alterdata Backup não está instalado neste computador.” Para a instalação do Alterdata Backup, será necessário pegar o executável com o CIRRUS e executar no cliente. Abaixo vou te mostrar a instalação dele que é bem simples. Atenção! O Alterdata Backup somente poderá ser instalado e executado através do AlterdataBackupBimer.exe e permanecer em execução no servidor de banco de dados. Após pegar o instalador AlterdataBackupFullInstall, execute-o como administrador. A primeira tela você selecionará “Serviço do Alterdata Backup” e “Módulo desktop do Alterdata Backup” e clicará em Próximo. Na tela seguinte, basta clicar em Instalar. Após a instalação do Alterdata Backup, o serviço será criado nos serviços do Windows. Certifique-se de que o serviço está ativo e executando. O AlterdataBackupBimer.exe não necessita instalação, basta somente executar. Ao executá-lo, ele abrirá a tela de login, assim como é feito com todos os outros módulos do Bimer normalmente. Mas, atenção!Não é permitido selecionar uma conexão que não esteja apontada para a mesma máquina na qual está abrindo o AlterdataBackupBimer.exe Observação: Conforme informado na introdução deste manual, o cliente não pagará para ter acesso ao Alterdata Backup, ele pagará apenas pelo armazenamento em nuvem. Esta validação da contratação do armazenamento será realizada pelo Alterdata Backup e não pelo AlterdataBackupBimer.exe. Por isso, nesta tela de login não será validada nenhum tipo de licença no Updater. Após realizar o login, o AlterdataBackupBimer.exe enviará os dados de conexão para abrir a interface do Alterdata Backup e, deste momento em diante, tudo será feito pelo próprio Alterdata Backup que já existia, porém, não possuía uma forma de login para clientes Bimer. O AlterdataBackupBimer.exe continuará sendo utilizado toda vez que o cliente Bimer quiser abrir a interface do Alterdata Backup para verificações e configurações, mas não precisará ficar em execução. Veremos, a partir de agora, o funcionamento do módulo. Ao abri-lo pela primeira vez, ele solicitará as configurações iniciais. Já adianto a você que as informações inseridas neste momento poderão ser alteradas posteriormente. A primeira configuração solicitada será o local você deseja que os arquivos backup sejam armazenados. Já é sugerido um diretório padrão, mas o cliente poderá alterar se quiser. Depois, será necessário informar a periodicidade e o horário que deseja que o backup seja feito. Há também a opção de realizar o backup manualmente. Em seguida, poderão ser adicionados e-mails para os quais o Alterdata Backup enviará avisos sobre a execução do backup. O cliente poderá adicionar um ou mais e-mails. Basta digitar o(s) e-mail(s) desejado(s) e clicar em Incluir. Na tela seguinte, você deverá informar quantos arquivos de backup serão mantidos. A cada agendamento executado, o Alterdata Backup fará a limpeza dos arquivos de backup presentes na pasta e excluirá o mais antigo. Por exemplo, se for escolhido manter 7 arquivos de backup, ao gerar o 8º arquivo, ele excluirá o primeiro backup que será o mais antigo, mantendo sempre apenas 7 arquivos de backup na pasta, evitando que o disco local do cliente fique muito cheio com arquivos muito antigos. Um ponto importante a ressaltar é que os arquivos serão excluídos de acordo com cada base. Mais a frente você verá que o sistema criará uma pasta para cada base, assim, a limpeza será feita individualmente nas pastas. Pronto, configurações iniciais realizadas! Atenção! É possível configurar backups de duas instâncias do SQL que possuem base com o mesmo nome. Exemplo: PAT1234/SQL2012 com a base Alterdata PAT1234/SQL2019 com a base Alterdata Desta forma o backup das duas bases será feito na mesma pasta e a exclusão automática não manterá, como no exemplo anterior, 7 arquivos para cada base. Caso o cliente queira alterar as configurações realizadas ou adicionar novas bases para realização dos backups, basta acessar o menu Geral dentro do Alterdata Backup. Neste menu: • Configurar base de dados: é possível editar a configuração da conexão já informada ou adicionar novas conexões; • Backup automático: é possível editar a periodicidade e o horário programados para a realização dos backups; • Diretórios do backup: é possível alterar o diretório no qual os backups serão armazenados. Além disso, nesta tela há um botão “Criar cópia” que funciona como um backup de redundância. Através deste botão, além do backup no diretório apontado, é possível direcionar um outro backup a outro local, como um HD externo, por exemplo; • Limpeza de arquivos: é possível alterar quantos arquivos serão mantidos no diretório; • E-mails para notificação: é possível alterar ou adicionar novos e-mails; • Assistente de configurações: é aberto novamente a tela das configurações inicias do Alterdata Backup. Na tela principal do Alterdata Backup, é mostrado do lado esquerdo o espaço em disco consumido e livre para armazenamento dos backups e, do lado direito, é mostrado o resumo de agendamentos realizados e próximos agendamentos. Quando o backup estiver em execução, o módulo sinalizará com uma notificação no canto superior direito, conforme imagem abaixo. Após finalizar o backup, no diretório configurado, o sistema gerará uma pasta para cada código de cliente, conforme imagem abaixo. Dentro da pasta com o código de cliente, há uma pasta para cada base. Veja abaixo: Os arquivos de backup serão compactados e ficarão com a extensão.bcir. Após descompactar, o arquivo passará a ter a extensão .sqlserver.bcir.tmp, mas o SQL reconhece este arquivo e o restaura corretamente! Quando o cliente contrata o armazenamento em nuvem, ao finalizar o backup local, o próprio Alterdata Backup já envia a cópia do arquivo para a nuvem. Assim, não é necessário que o cliente realize este procedimento manualmente.


## Informações importantes

Há algumas informações importantes que você precisa saber. Vamos a elas! • No Alterdata Backup, ao clicar em Fazer Backup, será realizado o backup de todas as bases configuradas; • É feito o backup da base _LGPD também, porém, deve ser configurado como uma nova base; • Em servidores que ainda não possuem conexões válidas no ERP.ini, não é possível restaurar backups. Isto se deve ao fato de que o AlterdataBackupBimer.exe precisa de uma conexão válida para efetuar o login no banco de dados e passar essas informações para abrir a interface do Alterdata Backup; • O sistema Alterdata Backup não existe na estrutura de banco de dados do Bimer. Assim, não é possível adicioná-lo para que este seja aberto junto ao Bimer; • Ainda não há definição se o AlterdataBackupBimer.exe substituirá o BackupERP.exe já existente; • Não funciona em ambientes Nuvem. Normalmente, os ambientes nuvem já possuem recursos de backup diário e, por isso, não há necessidade de realizar o backup através do Alterdata Backup. Por isso, ele apenas funciona para clientes que possuam infraestrutura local; • O Alterdata Backup não seguirá versão do Bimer; a versão dele é independente; • Agora é possível realizar o agendamento para o backup da base dos clientes Wise PCP. Sabemos que os clientes pedem a rotina de backup automático do Wise há algum tempo, porém, o GeAgente não faz backup de PostgreSQL. Mas, agora, com o Alterdata Backup, isso é possível.
